# 通用自检规则

## 只读原则

自检只允许读取文件和运行只读检查命令，不得修改、创建、删除或格式化项目代码文件。

允许创建临时分析输出时，必须先询问开发者；默认不落盘。

## 宏控检查

检查 MK 宏控时按以下规则处理：

1. 读取目标文件。
2. 忽略空行。
3. 忽略以 `#` 开头的注释行。
4. 识别形如 `KEY = value`、`KEY:=value`、`KEY=value` 的有效赋值。
5. 行尾注释不影响宏控值判断，但证据中保留原始行内容。
6. 如果存在目标宏控且有效值等于 SOP 期望值，结论为 `已适配`。
7. 如果不存在目标宏控，结论为 `未适配`。
8. 如果存在目标宏控但值不是 SOP 期望值，结论为 `未适配`，并报告实际值。
9. 如果同一宏控存在多个有效赋值且值互相冲突，结论为 `无法判断`。

比较宏控值时，去除值两端空格；大小写是否敏感按 SOP 原文执行。当前 SOP 的 `yes` 按小写精确匹配。

## 证据要求

每个特性的自检结果必须包含：

- 检查文件路径
- 检查的宏控或文件项
- 命中的有效行，或缺失说明
- 结论判定依据

如果文件不存在、路径无法推导或宏控冲突，必须把原因放入阻塞项。

## 辅助脚本使用

可选辅助脚本为：

```text
scripts/audio_feature_self_check.py
```

允许使用的子命令：

- `inspect`：解析项目编译选项并输出派生变量。
- `check-macro`：检查指定文件中的宏控值。
- `verify`：执行当前 SOP 支持特性的只读自检。

脚本只是工具，不得覆盖 SOP 判断，也不得隐藏不确定项。
