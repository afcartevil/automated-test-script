# Sensor物理距感口袋防误触问题分析

## 适用范围

- **问题类型**：物理距感状态上报异常导致口袋防误触模式异常
- **触发条件**：解锁界面遮挡距感
- **适用场景**：
  - 应该触发防误触界面，但没有触发
  - 不应该触发防误触界面，但是触发了
- **适用芯片平台**：MTK

## 前置条件

分析前需确认以下日志文件可用：

| 日志文件 | 必需性 | 用途 |
|----------|--------|------|
| `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/main_log_X__XXXX_XXXX_XXXXXX` | 必需 | 查看上层是否监听防误触状态、是否收到防误触状态以及是否展示UI |
| `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/scp_log_X__XXXX_XXXX_XXXXXX` | 必需 | 查看底层SCP侧是否上报口袋模式状态及对应时间 |

## 问题有效性确认

先确认问题是否属于sensor领域：

1. 超声距感属于audio模块，物理距感属于sensor模块分析。
2. 在 `scp_log` 中搜索 `anti_touch_ultrasound`。
3. 如果存在 `anti_touch_ultrasound`，则判定为超声距感防误触项目，问题不属于sensor领域，应转由audio模块分析。

## 分析原则

- 如果用户能提供问题发生时间，优先围绕该时间点附近的监听窗口做定向分析。
- 如果用户不能提供问题发生时间，不能只拿某一次关键词命中直接下结论，必须先枚举所有监听窗口。
- 一个有效分析窗口定义为“某次上层开始监听防误触”到“下一次上层开始监听防误触”之间的时间区间。
- 只允许在同一监听窗口内关联 `上层监听 -> SCP状态上报 -> main_log接收状态 -> UI展示` 四个阶段，禁止跨窗口拼接日志。

## 分析工作流

按以下步骤依次执行分析。用户未提供时间戳时，默认进入“候选监听窗口遍历模式”。

### 步骤1：枚举候选监听窗口
- **目标**：找到所有可能与问题相关的上层防误触监听事件
- **操作**：在 `main_log` 中搜索背部物理距感 `Sensor name="pdb"` 或正面物理距感 `Sensor name="anti_touch"`，记录每一个开始监听的时间戳
- **判断**：
  - 没有相关监听打印 -> 问题转由上层处理
  - 有相关监听打印 -> 为每次监听建立候选窗口，进入步骤2

### 步骤2：检查每个监听窗口内的SCP口袋状态上报
- **目标**：确认底层是否在每个监听窗口内上报口袋模式状态
- **操作**：在 `scp_log` 中搜索 `timesync|pdb:pre and now state|anti_touch: anti pre and now state`，将SCP时间换算为安卓时间，并检查每个监听窗口内是否出现 `0 1` 或 `1 0`
- **判断**：
  - 对于“误触发”问题：窗口内存在 `0 1` -> 底层识别到靠近，优先怀疑校准/结构/底噪问题；窗口内不存在 `0 1` -> 底层未上报进入口袋模式，问题倾向上层
  - 对于“应触发未触发”问题：窗口内不存在 `0 1` -> 底层未识别靠近，优先怀疑校准/测试手法/硬件问题；窗口内存在 `0 1` -> 底层已正常上报，进入步骤3

### 步骤3：检查上层接收状态与UI展示
- **目标**：确认底层每次进入口袋模式的上报，是否被上层接收并显示防误触界面
- **操作**：在 `main_log` 中搜索 `onSensorChanged distance|SHOW_INADVERTENTVIEW`，逐个匹配窗口内每一笔 `pdb:pre and now state is 0 1` 或 `anti pre and now state is 0 1`
- **判断**：
  - 上层没有收到口袋状态 -> 底层上报失败或链路传输异常
  - 上层收到了状态，但没有 `SHOW_INADVERTENTVIEW, VISIBLE` -> 上层口袋模式逻辑异常
  - 上层收到了状态，且出现 `SHOW_INADVERTENTVIEW, VISIBLE` -> 功能正常，优先复核测试手法

### 步骤4：输出候选窗口结论
- **目标**：输出带证据链的结论，避免抓错场景
- **操作**：汇总每个监听窗口中的监听时间、SCP状态上报内容与时间、main_log状态接收时间、UI展示时间，按问题现象筛选最相关窗口
- **判断**：
  - 仅一条窗口证据完整且异常最明显 -> 输出单一主结论
  - 多条窗口都可疑 -> 输出前3个候选窗口并标注置信度

详细分析操作与示例参阅 [ANALYSIS_STEPS.md](ANALYSIS_STEPS.md)。
