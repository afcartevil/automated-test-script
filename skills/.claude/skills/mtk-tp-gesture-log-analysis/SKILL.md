# MTK TP 灭屏手势日志分析

## 适用范围

- **问题类型**：TP 唤醒 / 灭屏手势功能不生效
- **适用场景**：
  - 灭屏双击唤醒无效
  - 灭屏画字母 / 滑动手势无效
  - 灭屏后偶现手势失效，亮屏后恢复
  - AOD / 灭屏切换后手势不生效
- **适用芯片平台**：MTK

## 前置条件

分析前优先确认以下日志已提供：

| 日志文件 | 必需性 | 用途 |
|---|---|---|
| `kernel_log` | 必需 | 检查 TP 驱动是否正常工作、灭屏时是否进入手势模式、TP 手势键值是否正常上报 |
| `main_log` | 必需 | 检查驱动上报的键值是否被上层接收和处理 |
| `sys_log` | 可选 | 辅助确认上层是否接收和处理驱动上报的键值 |

## 问题有效性确认

开始分析前，先确认：

- 设置侧已打开灭屏手势
- 同版本可多次复现

## 分析工作流

按以下顺序执行，完整细节参阅 [ANALYSIS_STEPS.md](ANALYSIS_STEPS.md)。

### 步骤1：获取日志
- **目标**：拿到与 TP 手势问题直接相关的日志
- **操作**：
  - 如果输入是 JIRA 号、目录或压缩包，先提取可分析日志
  - 只保留串口日志、`kernel_log`、Android 日志等 TP 相关日志
  - 若存在 `mobilelog`，优先读取其中的 `kernel_log` 和 `main_log`
  - 若存在 `mobilelog`，开机阶段日志优先查看其子目录 `booot_normal`
- **判断**：
  - 日志获取失败 -> 停止分析并说明缺失项
  - 日志获取成功 -> 进入步骤2

### 步骤2：日志过滤
- **目标**：缩小到 TP 手势关键路径
- **操作**：
  - `kernel_log` 搜索：`touch|fts|cts|gtp|nvt|chsc|ilitek|tcm`
  - `main_log` / `sys_log` 搜索：`KeyguardGesture|keycode`
- **判断**：
  - 过滤成功 -> 进入步骤3

### 步骤3：分析 `kernel_log`
- **目标**：确认 TP 驱动、手势模式切换、手势开关和键值上报是否正常
- **重点检查**：
  - TP 驱动是否正常加载和工作
  - 手势功能是否已开启
  - 亮灭屏状态切换时 TP 模式是否正确切换
  - 驱动是否已上报对应 TP 手势键值

### 步骤4：分析 `main_log` / `sys_log`
- **目标**：确认 framework 是否收到并处理 TP 手势
- **重点检查**：
  - 是否收到 `keyCode = 355` 等关键上报
  - 是否进入 `KeyguardGestureService`
  - 双击亮屏是否被口袋模式拦截
  - 音乐手势是否被错误的媒体状态拦截

## 约束

- 不要假装看过未提供的日志。
- 不要跳过 `kernel_log` 直接下结论为 framework 问题。
- 只有在 TP 已进入手势模式且已成功上报键值后，才可将问题进一步收敛到上层处理。
- 涉及双击亮屏时，必须检查口袋模式日志。
- 涉及音乐手势时，必须检查 framework 的媒体播放状态判断。
