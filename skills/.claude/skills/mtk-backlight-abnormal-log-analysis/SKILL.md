# MTK 平台 BackLight 设置异常/闪屏/黑屏 分析

## 适用范围

- **问题类型**：MTK平台显示领域背光设置异常
- **适用场景**：
  - Android/Linux 显示领域背光设置异常
  - 闪屏问题（含亮度短时跳变导致的闪高亮/闪暗）
  - 黑屏问题（含背光写0导致黑屏）
  - 上层设置背光与底层背光执行不一致问题
  - AAL/ESS自动调光引发的亮度异常问题
- **适用芯片平台**：MTK

## 不适用场景

- 非MTK芯片平台的显示问题
- 与背光设置无关的纯应用绘制显示异常
- 无法提供main/android log与kernel log的场景
- 仅术语解释类问答、无需完整SOP排查流程的场景
- 非显示领域的问题

## 前置条件

分析前需确认以下输入信息可用：

| 输入项 | 必需性 | 用途 |
|--------|--------|------|
| 问题设备的MTK芯片平台型号 | 必需 | 确认芯片平台匹配 |
| 问题复现步骤、发生概率 | 必需 | 确认问题可复现性 |
| 预期行为与实际异常描述 | 必需 | 明确异常现象 |
| `main_log` / Android log | 必需 | 分析上层是否设置背光 |
| `kernel_log` | 必需 | 分析底层是否设置背光 |
| 串口日志 | 可选 | 分析开机黑屏问题 |
| 近期修改的代码文件、可疑提交记录 | 可选 | 辅助定位 |

## 问题有效性确认

开始分析前，先确认：
1. Linux内核日志可正常打印
2. Android main log可正常获取
3. 芯片平台为MTK
4. 问题属于显示领域背光设置异常、闪屏或黑屏

## 分析工作流

按以下步骤依次执行，不得跳步、不得颠倒顺序。详细操作参阅 [ANALYSIS_STEPS.md](ANALYSIS_STEPS.md)。

### 步骤1：获取日志
- **目标**：获取与背光异常直接相关的日志文件
- **操作**：
  - 如果给定的是JIRA号、文件夹等非直接Log文件，先获取日志文件
  - 排除与显示领域无关的日志文件，仅保留串口日志、Kernel日志、Android日志等有效文件
  - 若存在mobilelog文件夹，需提取其中的`kernel_log`和`main_log`
  - 若存在mobilelog文件夹，开机阶段相关日志优先提取`boot_normal`子文件夹内文件
- **判断**：
  - 未获取到kernel_log或main_log -> 停止分析，向用户索要缺失日志
  - 已获取到必需日志 -> 进入步骤2

### 步骤2：日志关键字过滤
- **目标**：按关键字过滤日志，缩小分析范围
- **操作**：
  - 优先按以下关键字过滤日志（不区分大小写）：`power`、`backlight`、`brightness`、`aal`
  - 显示链路补充过滤关键字（不区分大小写）：`lcm`、`panel`、`LocalDisplayAdapter`、`led`
  - 按main_log与kernel_log分别整理过滤结果
- **判断**：
  - 过滤结果为空 -> 扩大关键字范围或确认日志是否正确
  - 过滤结果非空 -> 进入步骤3

### 步骤3：问题分类与链路分析
- **目标**：根据问题类型执行对应的链路分析
- **分类分析规则**：
  - **背光设置失效**：先读main_log判断上层是否修改背光，再读kernel_log判断底层是否设置背光
  - **闪屏**：先判断上层设置亮度是否存在跳变，再判断底层设置亮度是否存在跳变
  - **黑屏**：先判断Power状态是否变化，再判断是否背光写0导致黑屏；若为Power状态变化导致背光写0，需继续分析屏幕重启原因，重点检查是否ESD Recover触发
  - **亮度过低**：重点判断短时间内背光值是否由较高值快速降为较低值
- **辅助检查**：
  - 若上层和底层均无背光设置，可检查是否修改颜色模式，以及PQ、CCORR等模块状态变化
  - 分析时尽量追溯问题源头；若日志无直接证据，可给出猜测或建议，但不得编造事实

### 关键日志示例与解读

#### Framework 设置背光
Framework 的背光范围为0~1浮点值，出现该日志表示Framework在设置背光：
```text
LocalDisplayAdapter: set backlight: 0.5227298, nits = 287.49393, sdrBacklight = 0.52273595, sdrNits = 287.49728
```

#### 将背光值写入设备文件
若设备使用LED背光，上层会将背光值写入brightness节点：
```text
... write 2529 to /sys/class/leds/lcd-backlight/brightness, result: 0
```
注意：若设备使用HWC背光，背光值会随刷图一起设置，通常不会打印该日志。

#### Panel 驱动设置背光
背光到达底层后，通过Panel驱动的`lcm_setbacklight_cmdq`接口发送：
```text
[ 1614.525765] lcm_setbacklight_cmdq level = 939, mapped_level = 806 dimming_status = 1
```

#### LCD 屏幕 ESS 设置背光
若屏幕类型为LCD且支持ESS背光，AAL模块会根据直方图自动调节背光。上层AAL下发设置背光，底层最终仍调用Panel驱动`lcm_setbacklight_cmdq`接口。详情参阅 [KEYWORDS.md](KEYWORDS.md) 中的AAL相关日志示例。
