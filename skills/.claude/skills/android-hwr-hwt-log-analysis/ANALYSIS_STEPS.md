# HWR 详细分析步骤

## 总流程

1. 确认 HWR/HWT 类型
2. 检查 WDT 喂狗链路
3. 分析总线与硬件线索
4. 解析关键地址到函数
5. 归因并输出结论

## 步骤1: 异常归类

### 目标
区分 HWT 与 HWR，明确是否为升级复位链路。

### 操作
1. 查看 `_分析报告.txt` 与 `__exp_main.txt` 的异常分类。
2. 在 `SYS_REBOOT_REASON` 中确认 WDT/HWR 标志。
3. 记录异常时刻与复位触发顺序。

## 步骤2: WDT 喂狗链路检查

### 目标
定位哪个 CPU 或线程导致未按期喂狗。

### 操作
1. 在 `SYS_KERNEL_LOG` 搜索 `wdt|wdtk|kick|timeout|failed|error`。
2. 确认多核喂狗是否完整（所有在线 CPU 是否参与）。
3. 找到“最后一次正常喂狗”与“首次异常日志”时间点。
4. 锁定异常 CPU（如 CPU1 未继续喂狗）。

### 输出
- 异常 CPU
- 最后喂狗时间
- 关键错误日志

## 步骤3: 总线与硬件线索

### 目标
判断是否存在 bus timeout、存储超时或硬件访问异常。

### 操作
1. 查看 `SYS_LAST_CPU_BUS`:
   - `lastpc`
   - `systracker`
2. 若出现地址值，结合 DTS/寄存器映射查所属模块。
3. 在 `SYS_KERNEL_LOG` 搜索对应模块（如 `ufs`）与 timeout/error。

### 输出
- 可疑地址与模块归属
- 超时类型（总线/存储/外设）

## 步骤4: 地址解析与符号映射

### 目标
把关键 PC/栈地址映射到函数，形成代码级证据。

### 操作
1. 准备匹配版本 `vmlinux/ko`。
2. 如需偏移计算:
   - 从 `SYS_REBOOT_REASON` 提取参考符号地址（如 `oops_in_progress`）
   - 与 `vmlinux` 中同名符号地址相减得到 kernel offset
3. 关键 PC 减 offset 后做 `addr2line` 或 gdb 解析。
4. 若命中公共框架函数，继续向上层业务栈帧追踪。

### 输出
- 关键函数/文件
- 映射过程与偏移依据

## 步骤5: 根因判断与输出

### 根因分型
- 软件阻塞: 锁等待、死循环、不可中断阻塞导致喂狗中断
- 总线/存储问题: ufs/bus timeout 导致 CPU 长期等待
- 硬件异常: CPU/主板/DRAM 不稳定，日志证据偏硬件侧

### Jira 输出要求
1. 异常分类（HWT/HWR）
2. 异常 CPU 与喂狗链路证据
3. lastpc/systracker 与地址归属
4. 地址映射结果（函数级）
5. 结论置信度与下一步行动
