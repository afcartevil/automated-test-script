# Display Feature 导入

> 适用范围：Android/Linux/BootLoader 显示领域的 Feature 导入

---

## 约束条件

- 严格遵循`执行步骤`，禁止跳过或合并任何步骤
- 严格执行每个步骤下的所有子项、操作、打印、赋值、交互逻辑
- 当前步骤未完整执行完毕前，禁止进入下一步骤
- 只允许使用已定义的变量，禁止自动新增变量
- 出现未定义的变量时，提示用户手动补充后再继续
- 代码路径中使用 `<>` 标记的部分，必须使用对应的变量填充
- 文件搜索仅允许在当前 VSCode 工作区根目录内进行
- 未经用户确认，禁止将搜索范围扩大到工作区之外

## 变量定义

- `PROJECT_NAME`：项目名称，默认值为空
  - 示例：`cm5`、`x6857`

- `PLATFORM_NAME`：平台名称，默认值为空
  - 示例：`mt6789`、`mt6897`

- `BOARD_NAME`：主板名称，默认值为空
  - 示例：`h972`、`h895`

- `PANEL_TYPE`：屏幕类型，默认值为空
  - 示例：`lcd`、`oled`

- `KERNEL_VERSION`：内核版本，默认值为空
  - 示例：`6.1`、`6.12`

<!-- 项目的代码目录，建议将目录添加至工作区 -->
- `PROJ_FILE_NEW`：新项目代码目录，默认值为空
  - 示例：`tOS_mtk_A16_trunk`、`lj7_dev`

- `PANEL_NAME_1`：项目第一个屏幕的名称，默认值为空
  - 示例：`vtdr6126_fhdp_dsi_vdo_dsc_gvo_gvo_120hz_cm5.c`

- `PANEL_NAME_2`：项目第二个屏幕的名称，默认值为空
  - 示例：`nt37703a_fhdp_dsi_vdo_dsc_tm_tm_120hz_cm5.c`

- `PANEL_NAME_3`：项目第三个屏幕的名称，默认值为空
  - 示例：`nt37703a_fhdp_dsi_vdo_dsc_tm_chct_120hz_cm5.c`

- **步骤 1.5**：请求用户输入`内核版本`，保存至变量 `KERNEL_VERSION`

### 步骤 2：驱动代码规范检查

- **步骤 2.1**：定位屏幕列表文件
  - 屏幕列表文件的完整路径如下：
    - `<PROJ_FILE_NEW>\vendor\mediatek\proprietary\bootable\bootloader\lk2\project\<PROJECT_NAME>_<BOARD_NAME>.mk`
  - 完整打印搜索到的文件完整路径
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 2.2**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 2.1**

- **步骤 2.2**：获取项目支持的屏幕名称
  - 编译配置项 `MTK_LCM_LIST_SUPPORT` 中指定了项目支持的屏幕名称
  - 获取该配置项的值，依次保存至 `PANEL_NAME_1`、`PANEL_NAME_2`、`PANEL_NAME_3` 中
  - 逐条打印 `PANEL_NAME_1`、`PANEL_NAME_2`、`PANEL_NAME_3` 的值
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 2.3**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 2.2**

- **步骤 2.3**：获取 LK 屏幕驱动目录
  - 参考以下格式匹配 LK 屏幕驱动目录：
    - `<PROJ_FILE_NEW>\vendor\mediatek\proprietary\bootable\bootloader\lk2\dev\lcm\<PANEL_NAME_*>`
  - 依次打印匹配到的目录完整路径
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 2.4**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 2.3**

- **步骤 2.4**：获取 LK 屏幕驱动文件
  - 获取每个 LK 屏幕驱动目录下的驱动 `.c` 文件
  - 依次打印获取到的完整文件名
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 2.5**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 2.4**

- **步骤 2.5**：获取屏幕驱动结构体
  - 每个文件中都定义了驱动接口结构体，在文件末尾使用关键词 `LCM_DRIVER` 查找该结构体
  - 完整打印匹配到的结构体
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 2.6**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 2.5**

- **步骤 2.5**：驱动代码规范检查
  - 检查该结构体中是否定义了以下接口：
    - `lcm_init`
    - `lcm_init_power`
    - `lcm_suspend`
    - `lcm_suspend_power`
    - `lcm_resume`
    - `lcm_resume_power`
  - 如果存在，标记该检查项为 `PASS` ，打印 `接口规范，进行下一项检查`
  - 如果不存在，标记该检查项为 `FAIL`，打印 `接口不规范，请进行修改`
  - 执行**步骤 3**

### 步骤 3：LCM 信息查询

- **步骤 3.1**：检查设备能否连接
  - 终端执行命令：`adb devices`
  - 如果可以访问设备，执行**步骤 3.2**
  - 如果无法访问设备，执行以下步骤：
    - 打印信息：`未检测到设备！跳过当前检查项！`
    - 执行**步骤 4**

- **步骤 3.2**：读取屏幕信息
  - 执行命令：`adb shell "cat sys/kernel/tran_display/lcm_name"`
  - 完整打印输出值
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 3.3**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 3.2**

- **步骤 3.3**：检查屏幕名称是否正确
  - 检查从设备中读取的屏幕名称是否是任意 `PANEL_NAME` 之一
  - 如果是，标记该检查项为 `PASS` ，打印 `屏幕名称正确，进行下一项检查`
  - 如果不是，标记该检查项为 `FAIL` ，打印 `屏幕名称异常，请进行修改`
  - 执行**步骤 4**

### 步骤 4：读取屏幕背光节点

- **步骤 4.1**：检查设备能否连接
  - 终端执行命令：`adb devices`
  - 如果可以访问设备，执行**步骤 4.2**
  - 如果无法访问设备，执行以下步骤：
    - 打印信息：`未检测到设备！跳过当前检查项！`
    - 执行**步骤 5**

- **步骤 4.2**：读取背光节点
  - 执行命令：`adb shell "cat sys/class/leds/lcd-backlight/brightness"`
  - 完整打印输出值
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 5**
        - 标记该检查项为 `PASS` ，打印 `背光节点读取正确，进行下一项检查`
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 4.2**
        - 标记该检查项为 `FAIL` ，打印 `背光节点读取异常，请进行修改`
        - 执行**步骤 5**

### 步骤 5：LCM 屏幕列表中的顺序是否正确

- **步骤 5.1**：定位屏幕 LK 屏幕驱动列表文件
  - LK 屏幕驱动列表位于以下文件中：
    - `<PROJ_FILE_NEW>\vendor\mediatek\proprietary\bootable\bootloader\lk2\dev\lcm\mt65xx_lcm_list.c`
  - 打印定位到的文件完整路径
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 5.2**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 5.1**

- **步骤 5.2**：搜索支持的屏幕
  - 屏幕驱动按照顺序存放在 LK 屏幕驱动文件中的 `lcm_driver_list` 列表中
  - 按照项目名称 `<PROJECT_NAME>` 在 `lcm_driver_list` 中搜索支持的屏幕
  - 按照顺序打印搜索到的屏幕名称
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 5.3**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 5.2**

- **步骤 5.3**：检查屏幕顺序是否正确
  - 检查 `lcm_driver_list` 中搜索支持的屏幕顺序是否和以下顺序一致：
    - `PANEL_NAME_1`
    - `PANEL_NAME_2`
    - `PANEL_NAME_3`
  - 如果顺序一致，标记该检查项为 `PASS` ，打印 `屏幕顺序正确，进行下一项检查`
  - 如果顺序不一致，标记该检查项为 `FAIL` ，打印 `屏幕顺序异常，请进行修改`
    - 执行**步骤 6**

### 步骤 6：检查屏幕像素密度配置是否正确

- **步骤 6.1**：定位 Kernel 编译配置文件
  - Kernel 编译配置文件的路径如下：

  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 6.2**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 6.1**

- **步骤 6.2**：获取像素密度配置
  - Kernel 编译配置文件中的 `TRAN_LCD_DENSITY_SIZE` 配置屏幕的像素密度
  - 读取该文件中 `TRAN_LCD_DENSITY_SIZE` 的值
  - 完整打印匹配到的配置条目
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 6.3**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 6.2**

- **步骤 6.3**：检查设备能否连接
  - 终端执行命令：`adb devices`
  - 如果可以访问设备，执行**步骤 6.4**
  - 如果无法访问设备，执行以下步骤：
    - 打印信息：`未检测到设备！跳过当前检查项！`
    - 执行**步骤 7**

- **步骤 6.4**：读取设备的像素密度
  - 执行命令：`adb shell "wm density"`
  - 完整打印输出值
  - 请求用户确认是否正确：
    - 用户输入 `y` 或者 `1` 表示正确，执行**步骤 6.5**
    - 用户输入 `n` 或者 `0` 表示错误，重新执行**步骤 6.4**

- **步骤 6.5**：检查像素密度是否正确
  - 对比从设备读取的像素密度和 `TRAN_LCD_DENSITY_SIZE` 配置的值是否一致
  - 如果一致，标记该检查项为 `PASS` ，打印 `像素密度配置正确，进行下一项检查`
  - 如果不一致，标记该检查项为 `FAIL` ，打印 `像素密度配置异常，请进行修改`
    - 执行**步骤 7**
