# 宏控子技能

## 基本信息
- **name**: 宏控子技能
- **description**: 负责在代码A（原分支）和代码B（目标分支）的公共仓和私有仓中搜索并修改宏控代码，根据上下文变量X和Y进行宏控注入。支持多种文件类型（.h, .c, .cpp, .sh, .cfg, .json）。适用于宏控代码修改、C语言代码注入、版本升级宏控等场景。
- **version**: 1.0.0
- **env**:
  - model: claude-3-5-sonnet
  - python_version: 3.11+
  - dependencies: []

## 技能定位
本技能是MODEM大版本升级的"工人"之一，负责执行公共仓和私有仓宏控代码的修改操作：
1. 直接接收主控技能传来的公共仓和私有仓路径以及上下文变量
2. 在公共仓和私有仓中搜索需要修改的宏控代码
3. 根据C语言编码规则和脚本文件格式进行宏控注入
4. 处理大小写不一致、空格差异、行末注释等复杂情况
5. 区分公共仓和私有仓的不同处理逻辑
6. 统计修改结果并返回给主控技能

## 输入参数
从主控技能接收以下参数：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| Path_A_Pub | string | 代码A（原分支）的公共仓路径 |
| Path_A_Priv | string | 代码A（原分支）的私有仓路径 |
| Path_B_Pub | string | 代码B（目标分支）的公共仓路径 |
| Path_B_Priv | string | 代码B（目标分支）的私有仓路径 |
| X | string | RF参数版本号，从RF参数移植子技能获取 |
| Y | string | RF参数配置标识，从RF参数移植子技能获取 |
| BOM_Name | string | 原BOM名称，用于搜索 |
| BOM_Name_Target | string | 变更后的BOM名称，用于替换原BOM名称 |

## 执行流程
1. **验证输入参数**：检查Path_A_Pub、Path_A_Priv、Path_B_Pub、Path_B_Priv是否有效
2. **搜索原BOM名称**：
   - 在原分支公共仓(Path_A_Pub)的mcu/custom目录下搜索包含原BOM名称的文件
     - BOM名称在代码中使用双下划线格式：`__{BOM_Name}__`
     - 只搜索*.h, *.c, *.cpp文件
     - 排除log文件和其他不需要的文件
   - 在原分支私有仓(Path_A_Priv)中搜索包含原BOM名称的文件
     - 支持多种文件类型：*.h, *.c, *.cpp, *.sh, *.cfg, *.json
     - 根据文件类型使用不同的搜索格式
3. **定位目标文件**：
   - 根据原分支公共仓找到的文件路径，定位到目标分支公共仓(Path_B_Pub)对应的文件
   - 根据原分支私有仓找到的文件路径，定位到目标分支私有仓(Path_B_Priv)对应的文件
4. **智能甄别与替换BOM名称**：
   - **公共仓处理**：
     - 检查目标分支是否已做回导（所有项目都支持，不需要宏控）
     - 检查目标文件是否已包含变更后的BOM名称
     - 将原BOM名称替换为：`__{BOM_Name}__ || defined(__{BOM_Name_Target}__)`
   - **私有仓处理**：
     - 根据文件类型使用不同的替换格式
     - 源代码文件(.h, .c, .cpp)：使用双下划线格式
     - 脚本文件(.sh, .cfg, .json)：使用原始格式
5. **结果统计**：统计修改的文件数和修改位置（区分公共仓和私有仓）
6. **返回结果**：将修改结果传递给主控技能

## 输出结果
| 输出项 | 类型 | 说明 |
|--------|------|------|
| success | boolean | 修改是否成功 |
| message | string | 执行结果描述 |
| modified_files | integer | 修改的文件数量 |
| modified_locations | integer | 修改的代码位置数量 |
| details | array | 修改详情列表 |

## 注意事项
- 需要处理大小写不一致的情况
- 需要处理多空格、少空格的差异
- 需要处理代码行很长不换行时在行末加注释的情况
- 修改前需要备份原始文件
- 复杂修改需要询问用户确认
