# 详细分析步骤（SPD 检查项 + 工程取证）

> **本文件**规定「怎么做」；**SPD** 规定「查什么」。若与项目书面规范冲突，以项目最新规范为准；本骨架为默认执行顺序。

## 分析流程概览

```text
步骤0 确认输入与边界（检查项只来自 SPD）
  → 步骤1 锁定 SPD + 检查范围
  → 步骤2 从 SPD 展开可执行检查项表
  → 步骤3 在工程中取证（路径 + 摘录）
  → 步骤4 对照 SPD 分级
  → 步骤5 输出报告（矩阵对齐 SPD）
```

## 步骤 0：确认输入与流程边界

### 目标

明确产出为可追溯矩阵；不把非 SPD 文档误读成检查项清单。

### 操作

1. 确认具备：SPD（或条款表）、检查范围、工程路径。  
2. 若含复杂表格/附件，以用户提供的可解析版本为准。

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 已明确检查项必须源自 SPD | 通过 | 进入步骤 1 |
| 仅有片段、无法区分 SPD 与说明性文档 | 不通过 | 请用户指明 SPD 正文或条款表 |

## 步骤 1：锁定 SPD 与检查范围

### 目标

确定 **SPD** 的版本与范围，以及本次分支/SKU/模块边界。

### 操作

1. 记录 SPD 版本/修订信息（若有）。  
2. **必须**取得 SPD：链接、版本、章节或条款表路径。  
3. 写明检查范围：分支、机型/SKU、模块目录、debug/release、MR 文件列表等。  
4. 从 **SPD** 识别强制 / 推荐 / 条件项；在检查表中预留「生效条件」列。

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| SPD 可用且范围清晰 | 通过 | 进入步骤 2 |
| 无 SPD 或无法映射条款 | 阻塞 | 不得生成检查行；列出所需 SPD 信息 |

## 步骤 2：从 SPD 生成可执行检查项表

### 目标

**一行 = SPD 的一条检查要求**（表格行、条款或清单项），便于逐项取证与勾选。

### 操作

建议列结构：

| 检查 ID | SPD 原文/序号/条款 ID | 类型（强制/推荐/条件） | 生效条件 | 期望配置摘要 | 建议取证位置（若 SPD 有写） |
|---------|------------------------|------------------------|----------|--------------|---------------------------|

**原则**：子条款单独成行；条件项写清触发条件；**禁止**在无 SPD 依据时增加行。

### 本次提取范围限制

仅提取以下四类 SPD 检查项并生成检查表：

- 万能播放引擎
- 视频 HDR
- 画质增强
- 视频省电

不属于上述四类的 SPD 条款，本次不入表。

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 表行与 SPD 检查点一一对应 | 通过 | 进入步骤 3 |
| 行数对不上或无法溯源到 SPD | 暂停 | 回到步骤 1 补齐 SPD 或澄清表格结构 |

## 步骤 3：从工程收集证据

### 目标

为每个 **SPD 检查 ID** 取得 **路径 + 摘录**。

### 操作

1. 搜索、读文件或脚本输出；可按目录或优先级安排取证顺序。  
2. 每个 SPD 检查 ID 至少一条证据；可读多文件。  
3. 未读到的文件 **不得** 推断为通过。

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 所有 SPD 强制项均已尝试取证 | 通过 | 进入步骤 4 |
| 部分路径不存在或无权限 | 标记该 ID「证据不足」 | 仍进入步骤 4，报告中单列 |

## 步骤 4：逐项对照并分级

### 目标

对每个 **SPD 检查 ID** 给出结论标签；默认集见 [SKILL.md](SKILL.md)「步骤 4」。

### 操作（默认集）

- **已满足**：证据充分且符合 **SPD** 要求。  
- **缺失**：**SPD** 要求明确但工程未体现或明显不符。  
- **歧义**：**SPD** 或实现有多种合理解释，需产品/配置确认。  
- **不适用**：写明 NA 理由（如当前范围不含该 SKU）。  
- **多余（可选）**：仅在用户要求清理时，报告与现行 **SPD** 冲突的遗留项。

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 全部 SPD 检查 ID 已分级 | 通过 | 进入步骤 5 |
| 存在未覆盖 ID | 回到步骤 3 | — |

## 步骤 4.1：不满足项导入处理

### 目标

先完成检查，再对不满足项执行导入处理：满足项 `Pass`，不满足项按对应方法处理。

### 操作

1. 对四类专项按检查方法执行判定。  
2. **满足项**：直接标记 `Pass`。  
3. **不满足项**：按下列导入规则执行并记录状态：  
   - 万能播放引擎：依赖 visha 专项导入，不需要修改；未导入需在最终输出中提出。  
   - 视频 HDR：平台限制；平台支持即默认导入，参考“视频HDR平台能力”支持表。  
   - 画质增强：平台限制；D8300 及以上支持，未完成需做移植。  
   - 视频省电：NA。  
4. 无法当场导入的项，记录阻塞原因并放入“待导入项”清单。

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 所有不满足项都有导入动作或 NA 说明 | 通过 | 进入步骤 5 |
| 存在不满足项但未给导入动作 | 不通过 | 补齐导入方法与状态后再进入步骤 5 |

## 步骤 5：输出报告

### 目标

**执行矩阵**主键为 **SPD 检查 ID/条款**；列顺序以 SPD 与可读性为准。

### 操作

使用 [SKILL.md](SKILL.md) 中的报告骨架，并替换为项目自带章节名/字段（若有）。矩阵需包含“不满足时导入动作”和“状态（已导入/待导入/NA）”。

### 证据示例

**正常**：

```
SPD 检查 ID: SPD-12
结论: 已满足
证据:
  device/vendor/.../overlay.xml
  <feature name="example" enabled="true"/>
（与 SPD R12 要求一致）
```

**异常**：

```
SPD 检查 ID: SPD-12
结论: 缺失（证据不足）
说明: SPD 要求的路径在当前分支不存在，且无替代取证约定
```
