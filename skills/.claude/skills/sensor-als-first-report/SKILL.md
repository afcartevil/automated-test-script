# Sensor光感首笔上报问题分析

## 适用范围

- **问题类型**：Sensor光感首笔上报问题
- **适用场景**：
  - 光感第一笔数据上报异常导致亮屏异常
  - 亮屏时出现闪屏
  - 亮屏时出现屏幕先暗后亮
  - 亮屏时出现屏幕先亮后暗
- **适用芯片平台**：MTK

## 前置条件

分析前需确认以下日志文件可用：

| 日志文件 | 必需性 | 用途 |
|----------|--------|------|
| `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/main_log_X__XXXX_XXXX_XXXXXX` | 必需 | 查看上层下发注册sensor的时间，以及底层SCP侧sensor数据到达HAL层的打印时间 |
| `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/scp_log_X__XXXX_XXXX_XXXXXX` | 必需 | 查看sensor开始enable时间，以及sensor吐数据和上报数据的时间和情况 |
| `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/sys_log_X__XXXX_XXXX_XXXXXX` | 可选 | 查看sensor数据被上层应用比如自动背光、屏幕旋转等接收到sensor数据的时间点 |

## 问题有效性确认

在开始分析前，先确认问题有效性：

拨号 `*#801#` 进入开机工模查看sensor是否校准，如果已经进行校准，证明为软件问题。

## 分析原则

- 如果用户能提供问题发生时间，优先围绕该时间点附近的链路做定向分析。
- 如果用户不能提供问题发生时间，不能只拿某一次关键词命中直接下结论，必须先枚举所有候选链路。
- 一条候选链路至少要闭环关联 `注册 -> enable -> 首笔上报 -> HAL收数` 四个关键阶段。
- 如果多个候选链路都可能异常，要按异常程度排序输出，不能把不同时间段的日志拼成一条链路。

## 分析工作流

按以下步骤依次执行分析。用户未提供时间戳时，默认进入“候选链路遍历模式”。

### 步骤1：枚举候选注册事件
- **目标**：找到所有可能与问题相关的自动背光注册事件
- **操作**：在 `main_log` 中搜索关键字 `AutomaticBrightnessController|registerListenerImpl|OriginChannel`，把每一次自动背光注册都记为一个候选起点
- **判断**：
  - 没有光感注册相关打印 -> 问题出在上层，转单给上层
  - 有多次光感注册相关打印 -> 为每次注册记录时间戳、sensor type、下发频率，逐条进入步骤2

### 步骤2：为每个候选注册匹配对应enable
- **目标**：检查每个候选注册之后，底层SCP侧是否正常enable光感
- **操作**：在 `scp_log` 中搜索关键字 `timesync|principal.transceiver enable: 5`，为每个候选注册匹配时间上最近且晚于注册时间的enable
- **判断**：
  - 某个候选注册没有匹配到enable -> 该候选链路为通信链路异常候选
  - 某个候选注册匹配到enable -> 计算enable时间并确认其在注册之后，进入步骤3

### 步骤3：为每个候选enable匹配首笔上报
- **目标**：检查每个候选enable之后的首次上报时间是否正常
- **操作**：在每个候选enable之后，查找第一个 `*_als_sample` 或 `*_report_als`
- **判断**：
  - enable后约60ms没有出现首笔上报函数打印 -> 该候选链路为驱动首笔上报异常候选
  - 出现首笔上报打印且与enable差值在60ms附近 -> 该候选链路进入步骤4

### 步骤4：为每个候选首笔上报匹配HAL收数
- **目标**：检查HAL是否及时收到每个候选链路的首笔上报数据
- **操作**：在 `main_log` 中搜索关键字 `light value`，为每个候选首笔上报匹配后续最近一笔 `light value`
- **判断**：
  - `light value` 时间戳与SCP侧上报时间戳差值在40ms以内 -> 该候选链路基本正常
  - 差值大于40ms -> 该候选链路存在HAL收数延迟异常

### 步骤5：对所有候选链路排序并输出
- **目标**：避免抓错场景或把不同时间段日志串成一条链路
- **操作**：汇总所有候选链路的 `注册 -> enable -> 首笔上报 -> HAL收数` 时序和异常点，按异常程度排序
- **判断**：
  - 只有一条候选链路证据完整且异常最明显 -> 输出该链路为主结论
  - 存在多条可疑链路 -> 输出前3条候选并标注置信度，不给唯一绝对结论

详细的分析操作说明和日志示例，参阅 [ANALYSIS_STEPS.md](ANALYSIS_STEPS.md)。
