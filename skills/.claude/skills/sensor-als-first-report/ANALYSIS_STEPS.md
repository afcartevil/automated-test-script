# 详细分析步骤

## 分析流程概览

本SOP用于确认亮屏异常是否由光感首笔数据上报异常导致。用户无法提供准确问题时间时，默认进入候选链路遍历模式。核心链路为：

1. 在 `main_log` 中枚举所有自动背光注册事件，生成候选注册列表。
2. 在 `scp_log` 中结合 `timesync` 和 `principal.transceiver enable: 5` 为每个候选注册匹配对应enable。
3. 为每个候选enable匹配第一笔 `*_als_sample` 或 `*_report_als`，计算首笔上报时延。
4. 在 `main_log` 中为每个候选首笔上报匹配后续最近一笔 `light value`，计算HAL收数时延。
5. 对所有候选链路按异常程度排序，输出主链路或前3条候选链路。

## 步骤1：枚举候选注册事件

### 目标

找到所有可能与问题相关的自动背光注册事件。

### 操作

1. 打开 `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/main_log_X__XXXX_XXXX_XXXXXX`。
2. 搜索关键字：`AutomaticBrightnessController|registerListenerImpl|OriginChannel`。
3. 不要只取第一条命中结果，而是记录所有自动背光注册事件。
4. 为每条注册记录时间戳、光感器件型号、`sensor_type` 和下发频率。

### 日志示例

```text
04-16 11:22:20.840992 10987 11068 D SensorManager: registerListenerImpl sensor={Sensor name="stk35f62_als", vendor="sensortek", version=1, type=5, maxRange=65535.0, resolution=1.0, power=0.001, minDelay=125000} pid=10987 uid=1000 pkgname=android listener=com.android.server.display.AutomaticBrightnessController$2@3a9512

04-16 11:22:20.841424   997   997 I OriginChannel: batch: [5,165000000,0]
```

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 没有光感注册相关打印 | 问题出在上层 | 转单给上层 |
| 只有1条光感注册相关打印 | 直接以该注册为唯一候选 | 进入步骤2 |
| 存在多条光感注册相关打印 | 为每条注册建立候选链路，禁止跳过 | 逐条进入步骤2 |

## 步骤2：为每个候选注册匹配对应enable

### 目标

检查每个候选注册之后，底层SCP侧是否正常enable光感。

### 操作

1. 打开 `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/scp_log_X__XXXX_XXXX_XXXXXX`。
2. 搜索关键字：`timesync|principal.transceiver enable: 5`。
3. 对每个候选注册，利用 `timesync` 的SCP侧时间戳加8小时，大致定位上层下发注册sensor的时间点。
4. 在该时间点周围找到时间上最近且晚于注册时间的光感enable相关打印。
5. 通过 `enable` 的SCP启动时间与最近 `timesync` 的SCP启动时间戳差值，加上或减去 `timesync` 的SCP侧时间戳，换算出与 `main_log` 一致的时间戳。
6. 记录“候选注册 -> 候选enable”的匹配关系。

### 日志示例

```text
[903.474](0)[0] principal.timesync scp 903474729230 host 910300064592 offset 6826058823 tick 903474 sched 910309363400 android 04-16 03:22:16.337231
[907.978](0)[0] principal.transceiver enable: 5 165000000 0
```

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 某个候选注册没有相关enable打印 | 该候选链路为通信链路异常候选 | 保留该候选并继续处理其他候选 |
| 某个候选注册匹配到enable，但换算后时间早于注册时间 | 时序异常，需要重新核对timesync和匹配区间 | 继续复核该候选 |
| 某个候选注册匹配到enable，且enable时间在注册之后 | 底层已收到光感enable | 该候选进入步骤3 |

## 步骤3：为每个候选enable匹配首笔上报

### 目标

检查每个候选enable对应的首次上报时间是否正常。

### 操作

1. 对每个候选enable，在其打印之后继续向下搜索。
2. 查找该候选enable之后出现的第一个关键字：`*_als_sample` 或 `*_report_als`。
3. 计算每条候选链路的首笔上报时间与enable时间的差值。
4. 对比是否接近SOP要求的 `60ms` 左右。
5. 禁止把某个enable与其他时间窗口里的首笔上报拼接在一起。

### 日志示例

```text
stk型号光感：
[908.039](0)[0] deputy.TRAN_ALS stk3bfx_als_sample 3632: : lux-als-g-scale:12 404008 129258 0.000100

mn型号光感：
[514746.604](0) DEPUTY.[MN7991X] mn7991x_report_als 1530: =====> lux=94, ir=4, als=305
```

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 某个候选enable后60ms左右没有出现 `*_als_sample` 或 `*_report_als` | 该候选链路为驱动首笔上报异常候选 | 保留该候选并继续处理其他候选 |
| 有首笔上报打印，但时间差明显偏大 | 该候选链路存在第一笔数据上报偏慢问题 | 进入步骤4继续确认链路时延 |
| 有首笔上报打印，且差值在60ms附近 | 该候选链路底层SCP上报正常 | 进入步骤4 |

## 步骤4：为每个候选首笔上报匹配HAL收数

### 目标

检查HAL是否收到每个候选链路的首笔上报数据。

### 操作

1. 回到 `mobilelog/APLog_XXXX_XXXX_XXXXXX__X/main_log_X__XXXX_XXXX_XXXXXX`。
2. 搜索关键字：`light value`。
3. 拿到每条候选链路的SCP侧首笔上报时间戳后，在 `main_log` 中找到该时间戳后面的第一笔 `light value`。
4. 计算 `light value` 时间戳与SCP侧上报光感时间戳的差值。
5. 记录每条候选链路的 `注册 -> enable -> 首笔上报 -> HAL收数` 四段时间。

### 日志示例

```text
04-16 11:22:20.940225   997  1133 I HfLooper: light value = 12.000000
```

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 某条候选链路的 `light value` 与SCP首笔上报时间差值在40ms以内 | 该候选链路基本正常 | 进入步骤5 |
| 某条候选链路的差值大于40ms | 该候选链路存在HAL收数延迟异常 | 进入步骤5 |

## 步骤5：对所有候选链路排序并输出

### 目标

避免抓错场景或把不同时间段日志误拼成一条链路。

### 操作

1. 汇总所有候选链路的四个关键时间点：`注册时间`、`enable时间`、`首笔上报时间`、`HAL收数时间`。
2. 分别计算 `注册到enable`、`enable到首笔上报`、`首笔上报到HAL收数`、`总耗时`。
3. 按异常程度排序，优先级通常为：`无enable` > `无首笔上报` > `HAL收数超时` > `链路正常`。
4. 如果多条候选链路都可疑，输出前3条候选并标注对应时间窗口。
5. 如果只有一条候选链路证据最完整且异常最明显，则将其作为主结论。

### 判断条件

| 条件 | 结论 | 下一步 |
|------|------|--------|
| 只有一条候选链路证据完整且异常最明显 | 可以输出单一主结论 | 输出结论 |
| 存在多条可疑候选链路 | 不能下唯一绝对结论 | 输出前3条候选并标注置信度 |
| 所有候选链路都基本正常 | 该问题大概率不是光感首笔链路导致 | 输出结论 |

## 结论输出要点

- 明确给出 `注册时间 -> enable时间 -> 首笔上报时间 -> HAL收数时间` 四个时间点。
- 分别给出 `enable到首笔上报`、`首笔上报到HAL收数`、`总耗时`。
- 用户未提供问题时间时，必须说明总共枚举了多少条候选链路。
- 如果存在多个可疑时间窗口，必须输出候选窗口和排序理由。
- 结论只允许落到以下几类：
  - 上层未注册，转单给上层
  - 通信链路异常，enable未下发到底层
  - 驱动首笔数据上报异常或过慢
  - HAL收数过慢，第一笔数据链路异常
  - 光感链路正常，该问题不是光感导致
