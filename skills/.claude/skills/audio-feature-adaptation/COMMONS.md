# 通用执行规则

## 宏控更新

对特性文件中的每个 MK 宏控，按以下步骤处理：

1. 在目标文件中搜索该宏控。
2. 如果宏控存在且值正确，保持不变，并报告 `跳过：已正确配置`。
3. 如果宏控存在但值不同，只修改该宏控行。
4. 如果宏控不存在，添加到 Audio 宏控区域。
5. 如果无法明确识别 Audio 宏控区域，先询问开发者再选择插入位置。

如果文件已有本地赋值风格，优先保持原风格；否则使用特性 SOP 中展示的赋值符号。

## 文件复制规则

复制前：

1. 确认源文件或源目录存在。
2. 确认目标目录存在；不存在时可创建。
3. 如果目标文件不存在，执行复制。
4. 如果目标文件存在且与源文件字节一致，跳过。
5. 如果目标文件存在且内容不同，报告源路径和目标路径，并在覆盖前询问开发者。

不得删除目标目录中的无关文件。

## XML 与 JSON 规则

修改 XML/JSON 时优先使用结构化解析，并尽量保留原格式。

如果因为非标准语法、DTD 问题或 vendor 特殊格式导致结构化解析失败：

1. 简要说明解析失败原因。
2. 使用符合 SOP 的最小范围文本修改。
3. 修改后验证目标节点或属性存在。

如果 SOP 引用的 `path`、`param_id`、`CategoryType`、场景或 JSON key 不存在，先询问开发者再继续。

## 验证

每个特性执行后：

- 验证每个期望宏控值
- 验证每个复制文件存在
- 验证每个必要 XML/JSON 节点或属性存在
- 收集 SCM 提醒
- 收集手动调试提醒

如果验证失败，停止并报告阻塞项，不得静默继续。

## 辅助脚本使用

可选辅助脚本为：

```text
scripts/audio_feature_adapt.py
```

允许使用的子命令：

- `inspect`：推导项目名和平台名。
- `check-macros`：检查期望的 MK 宏控值。
- `plan-feature`：输出指定特性的文件、宏控和 SCM 提醒。
- `verify`：执行轻量级修改后检查。

脚本只是工具，不得覆盖 SOP 判断，也不得隐藏不确定项。
