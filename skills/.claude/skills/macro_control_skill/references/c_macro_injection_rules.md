# C语言宏控注入规则

## 概述
本文档定义了在C语言代码中进行宏控注入时需要遵循的规则和最佳实践。

## 基本规则

### 1. 宏定义格式
- **宏名称**：通常使用全大写字母，单词之间用下划线分隔
  - 正确: `#define MAX_BUFFER_SIZE 1024`
  - 错误: `#define max_buffer_size 1024`
- **宏值**：根据类型使用适当的格式
  - 数值: `#define TIMEOUT_MS 500`
  - 字符串: `#define VERSION "1.0.0"`
  - 表达式: `#define MIN(a,b) ((a) < (b) ? (a) : (b))`

### 2. 条件编译格式
- `#ifdef` / `#ifndef` / `#endif` 必须配对使用
- 条件编译块需要适当缩进
- 示例：
  ```c
  #ifdef FEATURE_ENABLED
      // 功能代码
  #endif
  ```

### 3. 空格处理
- **宏定义**：`#define` 后有一个空格，宏名和宏值之间有一个空格
  - 正确: `#define DEBUG 1`
  - 错误: `#define DEBUG1`（缺少空格）
- **条件编译**：`#ifdef` 后有一个空格
  - 正确: `#ifdef DEBUG`
  - 错误: `#ifdefDEBUG`

### 4. 注释处理
- **行末注释**：代码行可以在行末添加注释，使用 `//`
  - 示例: `#define DEBUG 1 // 调试模式开关`
- **块注释**：使用 `/* */` 进行多行注释
- **注意**：当代码行本身很长时，注释应单独占一行

### 5. 大小写处理
- **宏名称**：通常使用全大写
- **宏值**：根据上下文使用适当的大小写
  - 字符串值保持原有格式
  - 枚举值使用全大写
- **处理不一致**：当发现大小写不一致时，参考项目现有代码风格

### 6. 换行处理
- **长宏定义**：当宏值过长时，使用反斜杠 `\` 进行换行
  - 示例:
    ```c
    #define LONG_MACRO "This is a very long macro \
                       that spans multiple lines"
    ```
- **注意**：反斜杠后不能有空格

## 宏控注入模式

### 模式1：添加新宏定义
```c
// 在文件适当位置添加新宏
#define RF_VERSION "RF_V2.1.0"
#define CONFIG_TYPE CONFIG_TYPE_A
```

### 模式2：修改现有宏
```c
// 将旧值修改为新值
// 旧: #define RF_VERSION "RF_V1.0.0"
// 新: #define RF_VERSION "RF_V2.1.0"
```

### 模式3：添加条件编译块
```c
#ifdef NEW_FEATURE
    // 新功能代码
#endif
```

### 模式4：修改条件编译条件
```c
// 旧: #ifdef OLD_VERSION
// 新: #ifdef NEW_VERSION
```

## 最佳实践

### 1. 代码风格一致性
- 参考目标文件的现有代码风格
- 保持缩进、空格、注释风格一致

### 2. 错误处理
- 修改前检查文件是否存在
- 修改前备份原始文件
- 处理文件读写权限问题

### 3. 复杂修改确认
- 对于影响较大的修改，向用户展示修改预览
- 询问用户确认后再执行修改

### 4. 版本控制
- 修改后建议用户提交到版本控制系统
- 保留修改记录便于追溯

## 常见问题处理

### 问题1：大小写不一致
- 识别现有代码中的宏名称格式
- 保持与现有代码一致的风格

### 问题2：空格数量不一致
- `#define` 后保持一个空格
- 宏名和宏值之间保持一个空格

### 问题3：行末注释
- 当代码行很长时，注释单独占一行
- 注释与代码之间保持适当间距

### 问题4：换行宏定义
- 使用反斜杠进行换行
- 保持换行后的缩进一致
