# Skill 同步开发 — 强制自检规范

> **等级**：硬性门槛。每个 Step / 每个 Phase 开发完成后，**必须**完成自检并在交付说明中贴出结果，未通过不得声称「完成」、不得进入下一步。

与仓库通用规则配合：`.cursor/rules/00-change-control.mdc`、`tahp-verify-commit.mdc`。本文针对 `.cursor/skill-sync` 执行批次加严。

---

## 1. 何时自检

| 时机 | 要求 |
|------|------|
| 每个执行 Step 结束 | 跑本 Step 相关测试；`git status` / `git diff` 对照 Phase 文档文件清单 |
| 整个 Phase 结束 | 跑完整自动验证 + 手工冒烟 + 全文自检清单 |
| 发现需改「清单外」文件时 | **先停手** → 更新 Phase 文档 + 告知用户原因 → 获确认后再改 |

---

## 2. 自检清单（逐条勾选）

### 2.1 变更范围

- [ ] `git status` / `git diff` 中的**每一个**改动文件，均在当前 Phase「必须改」或已获批的「补充改」列表中
- [ ] 无顺手重构、无关格式化、无关重命名、无关注释大改
- [ ] 未改 `hermes-agent-main/`（除非 Phase 文档明确要求）
- [ ] 未提交/未改动密钥、`.env`、`unified-config.json`、本机 `skill-sync-state.json` 实数据

### 2.2 规划符合性

- [ ] 实现行为与当前 `PHASE-*.md` API / 状态机 / UI 描述一致
- [ ] 未提前实现下一 Phase 功能（例如 P1 不做包上传、Bundle CRUD）
- [ ] 双仓契约若有改动：两边已同批对齐，且文档已更新

### 2.3 质量：无异常 / 无报错

- [ ] 相关单测全部通过（零 fail）
- [ ] 涉及 Console 代码时：`cd tahp-console && npm run build` 通过
- [ ] 涉及中心时：`npm run smoke`（或等价）通过，或说明为何跳过
- [ ] 启动/调用新增 API 无未捕获异常；日志无 Unexpected / TypeError 级错误
- [ ] 前端相关：无编译错误；关键路径不白屏（含「中心未配置」降级态）

### 2.4 交付说明（必须输出给用户）

每次 Step/Phase 完成后，在回复中固定包含：

```markdown
## 自检报告
- 实际修改文件：（列表，对照文档）
- 与规划差异：无 | 有（见下）
- 验证命令与结果：…
- 已知问题：无 | …

### 若有规划外修改（特殊情况）
| 文件 | 原因 | 为何必须改 | 是否已更新文档 |
|------|------|------------|----------------|
| … | … | … | 是/否 |
```

**禁止**把规划外修改藏在 diff 里不说明。

---

## 3. 规划外修改的处理流程

1. **发现**需要改清单外文件（编译不过、漏挂路由、类型共享等）。
2. **停止**继续堆代码。
3. **告知用户**：文件路径、原因、最小改法、是否扩大影响面。
4. **更新**对应 `PHASE-*.md` 文件清单与变更记录。
5. **获确认**后再改；自检报告中单独列出「特殊情况」。

例外（可先改后在自检中说明，仍须写入文档）：

- 纯测试夹具路径错误导致本批新测无法跑通
- import 路径漏改导致 `npm run build` 失败，且改动 ≤2 行、无行为变化

即便是上述例外，也必须在自检报告中写明原因。

## 4. 推荐验证命令

### 客户端（easyadapter）

```bash
cd E:/TAHP/easyadapter
git status
git diff --stat

cd tahp-console
npm test
npm run build
```

### 中心（easyadapter_bff）

```bash
cd E:/TAHP/easyadapter_bff
git status
git diff --stat
npm run smoke
```

### 范围核对（对照文档）

将 `git diff --name-only` 与当前 Phase「必须改」表逐行比对；多出的文件 = 规划外，走 §3。

---

## 5. 不合格判定（任一即不通过）

- 测试或 build 失败仍称完成
- 存在未说明的规划外文件
- 运行时明确报错未修复也未降级说明
- 实现了未在文档中的「顺手功能」
