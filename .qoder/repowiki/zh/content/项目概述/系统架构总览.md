## 引言
TAHP（TECNO AI Harness Platform）是一个服务于传音Android底软集成部的双引擎AI平台，基于"Agent = Model + Harness"范式构建。平台通过约束驱动与EvoSkill自动进化，实现诊断引擎（Bug分析）与适配引擎（版本升级/功能移植/运营商移植）的自动化闭环。

**重大更新**：v3.2版本引入了知识库v3.0架构层，作为双引擎的基础设施，实现知识自动沉淀、文档投喂、约束自动提取和跨模块知识复用。知识库采用SQLite + ONNX嵌入函数的向量数据库架构，支持语义检索和跨模块查询。

- 诊断引擎：围绕通话/短信/功耗/内核等场景，完成日志采集→根因定位→方案生成→验证输出的全流程。
- 适配引擎：面向AOSP Diff分析→影响评估→代码生成→验证的批量适配流程，覆盖版本升级、特性移植与运营商移植。
- **知识库v3.0**：全新的知识基础设施，包含技术文档、经验案例、错误模式、ChromaDB向量数据库、知识查询MCP工具等五大组件。

平台采用Harness六层架构设计，自下而上分别为：信息边界层、工具系统层、执行编排层、记忆状态层、评估观测层、约束校验层。通过MCP（Model Context Protocol）标准化工具接入，结合Git与EvoSkill实现Skill的自动进化与跨模型迁移。

## 项目结构
仓库采用按域/模块组织的层次化结构，核心目录与职责如下：
- constraints/：业务约束（Owner唯一输入端），按模块与共享规则组织
- skills/：自动生成/维护的AI Skills，支持Claude与Codex格式
- playbooks/：执行编排剧本（Pipeline定义），描述跨Agent协作流程
- tools/：MCP工具接口定义，统一能力抽象
- scripts/：自动化脚本，包括EvoSkill运行、评估、质量门禁、知识库管理等
- db/：知识库与向量化检索
- knowledge-base/：知识库文件存储，包含技术文档、经验案例、错误模式等
- docs/：深度文档与规范
- reports/：评估报告输出
- tahp-mcp-server/：MCP服务器，提供知识查询等工具服务

## 详细组件分析

### 双引擎工作流程

#### 诊断引擎（Bug分析）
- 流程：日志采集 → 根因定位（Framework/RILJ/RILC/Modem层级）→ 方案生成（修复建议/影响评估）→ 验证输出（质量门禁）
- 层级判定顺序：Framework（Java）→ RILJ（Java RIL）→ RILC（C/HIDL）→ Modem
- 必产出维度：根因层级、复现概率、影响范围、修复类型、严重程度、根因描述、修复建议
- **新增知识库集成**：通过tahp_query_knowledge工具查询相关经验案例和错误模式

```mermaid
flowchart TD
Start(["开始：收到Bug描述"]) --> Collect["日志采集<br/>logcat/AT命令/Modem日志"]
Collect --> QueryKB["知识库查询<br/>tahp_query_knowledge<br/>历史案例/错误模式"]
QueryKB --> Layer1["层级判定：Framework"]
Layer1 --> Layer2["层级判定：RILJ"]
Layer2 --> Layer3["层级判定：RILC"]
Layer3 --> Layer4["层级判定：Modem"]
Layer4 --> Evidence["证据链构建"]
Evidence --> RootCause["根因确认"]
RootCause --> Plan["修复建议与影响评估"]
Plan --> Gate["质量门禁检查"]
Gate --> |通过| Output["输出分析报告"]
Gate --> |失败| Retry["失败恢复/重试回滚"]
```

### 知识库v3.0架构层详解

#### 五大核心组件
- **技术文档**：从约束文件自动提取的技术文档，支持YAML和Markdown格式
- **经验案例**：历史问题解决案例的自动沉淀，包含修复方案和最佳实践
- **错误模式**：常见错误类型的结构化知识，支持跨模块复用
- **ChromaDB向量数据库**：基于ONNX all-MiniLM-L6-v2模型的384维向量嵌入
- **知识查询MCP工具**：tahp_query_knowledge工具，支持语义检索和跨模块查询

#### 知识库配置
```yaml
version: "1.0"
database:
  type: sqlite-onnx    # SQLite 持久化 + ONNX 语义嵌入（纯 Python，零 C++ 依赖）
  persist_dir: .knowledge_db/
  embedding_model: default  # onnxruntime + all-MiniLM-L6-v2 (384d)
sources:
  manual_feed: true
  auto_capture: true
  cross_module_sync: true
retrieval:
  default_top_k: 5
  min_confidence: 0.05      # 低阈值以支持跨语言检索（英文模型查中文内容）
  cross_module_top_k: 3
  rerank: false
constraint_extraction:
  auto_trigger: true
  owner_review_required: true
  confidence_threshold: 0.75
```

## 故障排查指南
- 约束文件缺失或不合规：检查对应模块的约束文件是否齐全，特别是必填字段与错误提示
- 工具执行失败：确认MCP工具接口实现（名称/描述/输入模式/处理器）与前置验证
- 评估失败：查看评估报告中的单项指标与错误信息，定位输出格式或安全违规
- 知识库检索异常：确认嵌入函数可用性与最小置信度设置
- **知识库初始化失败**：检查ChromaDB配置、SQLite数据库连接、ONNX嵌入函数可用性
- **知识查询工具异常**：确认tahp_query_knowledge工具配置和权限设置
- **跨模块检索失败**：检查模块排除配置和跨模块Top-K设置

## 结论
TAHP通过双引擎架构与Harness六层设计，实现了从约束到执行、从评估到进化的完整闭环。**v3.2版本的重大升级**引入了知识库v3.0架构层，作为双引擎的基础设施，实现了知识自动沉淀、文档投喂、约束自动提取和跨模块知识复用。MCP标准化工具接入与EvoSkill自动进化机制，使得平台能够在诊断与适配两大场景中高效落地，并通过跨模块检索与跨模型迁移实现知识与能力的复用与扩展。

知识库采用SQLite + ONNX嵌入函数的向量数据库架构，支持语义检索和跨模块查询，为平台提供了强大的知识支撑能力。依托质量门禁与失败恢复机制，平台在保证安全性与稳定性的同时，持续提升自动化水平与交付效率，为未来的智能化升级奠定了坚实基础。
