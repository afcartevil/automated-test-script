# 知识库列表管控完善方案 (plan1404)

## 问题诊断

| # | 问题 | 根因 |
|---|------|------|
| 1 | 知识条目批量归档/删除只能全操作，无法选择性处理 | entryColumns 无 selection 列，批量按钮无上下文 |
| 2 | Skill 草稿只能单条操作，无全选/多选/批量 | draftColumns 无 selection 列，无批量操作入口 |
| 3 | 文档库只能查看和删除，无编辑能力 | 文档卡片只有 reader drawer，无编辑表单 |
| 4 | Skill 工坊已生成的仍在推荐；草稿列表只有编辑/发布 | getSkillSuggestions 不排除已有草稿；draft-list 模板缺删除按钮 |

## 设计原则

- **行选择 + 浮动批量栏**: 参考 GitHub / Notion / Linear 的列表管理模式，选中行后底部浮出操作栏，显示选中数 + 可用操作
- **单条操作保留**: 行内按钮保留用于快速单条操作，批量栏用于多选场景
- **最小侵入**: 复用现有 NDataTable 组件能力（`row-key` + `checked-row-keys`），不引入新组件库

## Task 1: 知识条目 — 行选择 + 选择性批量操作

### 前端改动 (`KnowledgeBaseView.vue`)

- `entryColumns` 头部新增 `{ type: 'selection' }` 列
- NDataTable 添加 `:row-key` + `v-model:checked-row-keys="checkedEntryKeys"`
- 新增响应式变量 `checkedEntryKeys = ref<string[]>([])`
- 移除工具栏"批量归档"/"批量物理删除"全局按钮
- 表格下方新增浮动批量操作栏（选中后显示）：
  - 已选 N 项 | 取消选择 | 批量归档 | 批量物理删除
- `doBulkArchiveEntries()` 改为只归档 `checkedEntryKeys` 中的条目，传 `{ ids: checkedEntryKeys.value }`
- `doBulkDeleteArchived()` 改为只删除 `checkedEntryKeys` 中的条目，传 `{ ids: checkedEntryKeys.value }`

### 后端改动 (`knowledge.ts` 路由)

- `POST entries/bulk-archive`: 新增 `ids?: string[]` 可选参数
  - 有 ids 时只归档指定条目
  - 无 ids 时保持原逻辑（按 module/before 筛选）
- `POST entries/bulk-delete`: 新增 `ids?: string[]` 可选参数
  - 有 ids 时只删除指定条目
  - 无 ids 时只删除 archived 状态条目

### 前端 API 改动 (`knowledge.ts`)

- `bulkArchiveEntries` filter 参数新增 `ids?: string[]`
- `bulkDeleteArchived` filter 参数新增 `ids?: string[]`

## Task 2: Skill 草稿 — 行选择 + 批量操作

### 前端改动 (`KnowledgeBaseView.vue`)

- `draftColumns` 头部新增 `{ type: 'selection' }` 列
- NDataTable 添加 `:row-key` + `v-model:checked-row-keys="checkedDraftKeys"`
- 新增响应式变量 `checkedDraftKeys`、`bulkDraftLoading`、`showBulkRejectModal`、`bulkRejectReason`
- 表格下方新增浮动批量操作栏（选中后显示）：
  - 已选 N 项 | 取消选择 | 批准 | 拒绝 | 删除 | 归档
  - 按钮按选中集状态智能启用/禁用
- 新增批量操作函数：
  - `doBulkApproveDrafts()` — 批量批准（调用 `bulkApproveDrafts` API）
  - `doBulkRejectDrafts()` — 弹出原因输入框后批量拒绝
  - `doBulkDeleteDrafts()` — 批量删除（仅 draft/rejected）
  - `doBulkArchiveDrafts()` — 批量归档（仅 approved/deprecated）
- 新增"批量拒绝"弹窗 (`showBulkRejectModal`)

### 后端新增路由 (`knowledge.ts`)

- `POST skill-drafts/bulk-approve` — 批量批准草稿
- `POST skill-drafts/bulk-reject` — 批量拒绝草稿（支持 reason 参数）
- `POST skill-drafts/bulk-delete` — 批量删除草稿（仅 draft/rejected）
- `POST skill-drafts/bulk-archive-selected` — 批量归档草稿（仅 approved/deprecated）

### 前端 API 新增函数 (`knowledge.ts`)

- `bulkApproveDrafts(draftIds: string[]): Promise<{ approved: number }>`
- `bulkRejectDrafts(draftIds: string[], reason?: string): Promise<{ rejected: number }>`
- `bulkDeleteDrafts(draftIds: string[]): Promise<{ deleted: number }>`
- `bulkArchiveSelectedDrafts(draftIds: string[]): Promise<{ archived: number }>`

## Skill 生成流程修复 (追加)

### 问题诊断

| # | 问题 | 根因 |
|---|------|------|
| 1 | 生成弹框一闪而逝 + 草稿不存在 | LLM 失败时 fallback 模板极简，生成极快(<1s)，弹窗立即关闭；草稿列表未刷新，状态筛选可能过滤 |
| 2 | Skill 内容来源不足 | `buildSkillGenPrompt` 每条 entry 截断 800 字符，8 条 x 800 = 6400 字符碎片上下文；原文档 6000+ 字符完整内容未使用 |

### Task 1: 弹框 Bug 修复

**前端 (`KnowledgeBaseView.vue`)**:
- `onGenJobCompleted` 改造：
  - 完成时先 `await loadDrafts()` + `await loadSkillSuggestions()`，再延迟 1.5s 关闭弹窗
  - 通过 `getSkillDraft(draftId)` 验证草稿确实存在
  - LLM 失败时不自动关闭弹窗，显示红色错误状态，让用户手动确认
  - 成功后自动切换到草稿 Tab，清除 `draftStatusFilter` 确保新草稿可见
  - 新增相似 Skill 检测分支处理（之前未处理）
- `subscribeGenProgress` SSE 错误重试：
  - 新增 `genSseRetryCount` 计数，最多重试 3 次
  - 每次重试延迟 2s 后重新连接 SSE
  - 重试用尽后 fallback 到 `pollJobStatus()` 轮询（3s 间隔）

**后端 (`knowledge.ts` 路由)**:
- LLM fallback 模板增强：包含条目关键词、源文档信息、前 8 条条目内容摘要
- `SkillGenJob.result` 新增 `llm_error_detail?: string` 字段

### Task 2: 文档源生成改造

**后端 (`knowledge.ts`)**:
- `runSkillGenerationStream` 新增 Step 0.5：
  - 从条目 `source_document_id` 反查或前端传入 `document_ids`
  - 通过 `readDocument()` 加载完整文档内容
  - emit 日志：`已加载 N 个源文档，共 X 字符`
- `buildSkillGenPrompt` 重构：
  - 新增参数 `documents?: KnowledgeDocument[]`
  - 优先使用文档全文（每个截取前 8000 字符），fallback 到条目拼接
  - 条目信息保留为元数据（关键词、置信度、分类）
  - Prompt 指导 LLM 保留关键技术细节、代码片段
- `skill-suggestions` 路由：每个 suggestion 返回 `source_document_ids: string[]`
- `generate-stream` 路由：新增 `document_ids?: string[]` 参数透传

**前端 API (`knowledge.ts`)**:
- `SkillSuggestion` 新增 `source_document_ids?: string[]`
- `SkillGenJobResult.result` 新增 `llm_error_detail?: string`
- `startGenerateStream` 参数新增 `document_ids?: string[]`

**前端 (`KnowledgeBaseView.vue`)**:
- `doGenerateSkill` / `handleForceCreate` 传递 `document_ids: suggestion.source_document_ids`
- 推荐卡片显示 “N 个源文档” 信息（绿色标识）
